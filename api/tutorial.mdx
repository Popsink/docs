This guide walks through the full lifecycle of a replication over the Popsink REST API: authenticate, pick an environment and a team, create a source and a target connector, subscribe the source's data models to the target, then start and monitor the workers.

<Note>
Every Popsink instance serves its own live OpenAPI schema. It is the source of truth for request and response shapes:

- Swagger UI: `https://<your-instance>/api/docs`
- OpenAPI spec: `https://<your-instance>/api/openapi.json`
</Note>

## Quick start

```bash
export POPSINK_URL="https://<tenant>.<region>.popsink.com"

# 1. Get a token (email + password)
TOKEN=$(curl -sS -X POST "$POPSINK_URL/api/auth/jwt/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "username=user@example.com" \
  --data-urlencode "password=secure123" | jq -r .access_token)

# 2. Use it on every call
curl -sS "$POPSINK_URL/api/envs/" -H "Authorization: Bearer $TOKEN"
```

## Concepts

```
environment
  └── team
        ├── source connector          reads a source system (CDC, batch or Kafka)
        │     └── data model          one per replicated table / collection / topic
        │           └── subscription  delivery of that data model to one target
        └── target connector          writes to the destination
```

| Concept | Description |
|---------|-------------|
| **Environment** | Top-level scope. Nearly every list endpoint is filtered by environment |
| **Team** | A group of users inside an environment. Connectors belong to a team |
| **Connector** | A source or a target, identified by its `connector_type` (e.g. `POSTGRES_SOURCE`, `SNOWFLAKE_TARGET`) |
| **Data model** | One stream produced by a source connector: a table, a collection or a Kafka topic. Created automatically from the source's table list |
| **Subscription** | Delivers one data model to one target connector, with its target table, column mapping, backfill and error-table settings |

## API overview

### Base URL

All endpoints live under `/api`:

```
https://<tenant>.<region>.popsink.com/api/
```

Trailing slashes are part of the path: use `/connectors/`, not `/connectors`.

### Authentication

Every endpoint except login requires a bearer token:

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### Pagination

List endpoints are paginated with `page` (starting at `1`) and `size` (default `50`, max `100`). They return:

```json
{
  "items": [ ... ],
  "total": 132,
  "page": 1,
  "size": 50,
  "pages": 3
}
```

### Idempotent creation

`POST /envs/`, `POST /teams/` and `POST /connectors/` accept an `Idempotency-Key` header. A retried call with the same key and body returns the original response instead of creating a duplicate:

```bash
-H "Idempotency-Key: 7f9c2ba4-e88f-11ee-a951-0242ac120002"
```

### HTTP status codes

| Code | Meaning | When you'll see it |
|------|---------|-------------------|
| `200` | Success | `GET`, `PATCH` |
| `201` | Created | `POST` that creates a resource |
| `202` | Accepted | Asynchronous operations (start/stop a connector, a data model or a subscription) |
| `204` | No Content | `DELETE`, bulk member creation |
| `400` | Bad Request | Wrong password, invalid input |
| `401` | Unauthorized | Missing or expired token |
| `403` | Forbidden | You are not a member of the team that owns the resource |
| `404` | Not Found | Unknown resource |
| `409` | Conflict | A resource with the same name already exists |
| `422` | Validation Error | The body does not match the schema |
| `429` | Too Many Requests | Too many failed login attempts |

## Step 1: Authenticate

You can get a token in two ways.

### Option A: email and password

```bash
curl -X POST "$POPSINK_URL/api/auth/jwt/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "username=john.doe@company.com" \
  --data-urlencode "password=MySecurePassword123!"
```

**Response (200 OK):**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

When the access token expires, exchange the refresh token for a new pair:

```bash
curl -X POST "$POPSINK_URL/api/auth/jwt/refresh" \
  -H "Content-Type: application/json" \
  -d '{"refresh_token": "'"$REFRESH_TOKEN"'"}'
```

### Option B: organization API key (self-hosted)

Create an API key in the control plane under **Dashboard → API keys → Create**. It starts with `psk_`, is shown once, and grants access to a chosen set of environments.

```bash
curl -X POST "$POPSINK_URL/api/auth/jwt/login-from-api-key" \
  -H "Content-Type: application/json" \
  -d '{"api_key": "'"$POPSINK_API_KEY"'"}'
```

The returned token lasts **10 minutes** and comes with no refresh token: exchange the key again when you get a `401`.

<Warning>
API-key login only works on deployments running in self-hosted mode. Otherwise it returns `400 This endpoint is only available in SELF_HOSTED mode`. Check `GET /api/config/deployment` → `deployment_mode`.
</Warning>

### Creating a user

`POST /auth/register` creates a user with an email and a password. It only exists when the deployment allows self-registration (otherwise it returns `404`). The server decides the `is_active`, `is_superuser` and `is_verified` flags itself and ignores them in the body.

```bash
curl -X POST "$POPSINK_URL/api/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"email": "jane.smith@company.com", "password": "SecurePass456!"}'
```

From now on, every example sends `-H "Authorization: Bearer $TOKEN"`.

## Step 2: Pick an environment

List the environments you can reach:

```bash
curl "$POPSINK_URL/api/envs/" -H "Authorization: Bearer $TOKEN"
```

```json
{
  "items": [
    { "id": "d455a981-be17-455e-a03c-4d9c3224db72", "name": "production" }
  ],
  "total": 1, "page": 1, "size": 50, "pages": 1
}
```

Endpoints that take no `env` / `env_id` parameter use your **active environment**. Set it explicitly:

```bash
curl -X PATCH "$POPSINK_URL/api/users/me" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"active_env_id": "d455a981-be17-455e-a03c-4d9c3224db72"}'
```

### Creating an environment

An environment needs the Kafka broker that stores its retention (used for replay and lifecycle management):

```bash
curl -X POST "$POPSINK_URL/api/envs/" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "production",
    "retention_configuration": {
      "bootstrap_server": "broker.kafka.svc:9092",
      "security_protocol": "SASL_SSL",
      "sasl_mechanism": "SCRAM-SHA-512",
      "sasl_username": "popsink",
      "sasl_password": "broker-password"
    }
  }'
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | ✅ | Environment name |
| `retention_configuration.bootstrap_server` | string | ✅ | Broker address |
| `retention_configuration.security_protocol` | string | ✅ | `PLAINTEXT`, `SASL_PLAINTEXT`, `SASL_SSL`, `SSL` |
| `retention_configuration.sasl_mechanism` | string | ✅ | `PLAIN`, `SCRAM-SHA-256`, `SCRAM-SHA-512`, `GSSAPI`, `OAUTHBEARER` |
| `retention_configuration.sasl_username` | string \| null | ✅ | SASL username (`null` without SASL) |
| `retention_configuration.sasl_password` | string \| null | ✅ | SASL password (`null` without SASL) |
| `retention_configuration.ca_cert` / `cert` / `key` | string | ⬜ | TLS / mutual TLS material |
| `retention_configuration.group_id` | string | ⬜ | Consumer group |

The response never returns the broker credentials.

```
ENV_ID=d455a981-be17-455e-a03c-4d9c3224db72
```

## Step 3: Create a team

```bash
curl -X POST "$POPSINK_URL/api/teams/" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "data-engineering",
    "description": "Team responsible for the CDC pipelines",
    "env_id": "'"$ENV_ID"'"
  }'
```

**Response (201 Created):**

```json
{
  "id": "881e0fce-5caa-4f5c-82c6-5eb883c47100",
  "name": "data-engineering",
  "description": "Team responsible for the CDC pipelines",
  "env_id": "d455a981-be17-455e-a03c-4d9c3224db72"
}
```

Add users as owners (admins of the team) or members. Users who already belong to the team are skipped:

```bash
curl -X POST "$POPSINK_URL/api/teams/$TEAM_ID/members/bulk" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "owners": ["3b0c298a-062e-42d1-a01b-277fa66908da"],
    "members": ["32d4b09d-4527-40d5-923b-e166d85cb459"]
  }'
```

**Response:** `204 No Content`. List them with `GET /teams/$TEAM_ID/members`.

```
TEAM_ID=881e0fce-5caa-4f5c-82c6-5eb883c47100
```

```bash
curl -X POST "$POPSINK_URL/api/postgres-source/check-credentials" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "host": "pg.company.com",
    "port": 5432,
    "database": "shop",
    "user": "popsink",
    "password": "pg-password"
  }'
```

```json
{ "is_success": true, "message": "Credentials are valid." }
```

Then list the tables you can capture:

```bash
curl -X POST "$POPSINK_URL/api/postgres-source/list-tables" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "host": "pg.company.com", "port": 5432, "database": "shop", "user": "popsink", "password": "pg-password" }'
```

## Step 5: Create the source connector

```bash
curl -X POST "$POPSINK_URL/api/connectors/" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "shop-postgres",
    "connector_type": "POSTGRES_SOURCE",
    "team_id": "'"$TEAM_ID"'",
    "json_configuration": {
      "host": "pg.company.com",
      "port": 5432,
      "database": "shop",
      "schema": "public",
      "user": "popsink",
      "password": { "valueFrom": { "secretName": "shop-pg", "key": "password" } },
      "whitelist": "public.orders,public.customers"
    }
  }'
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | ✅ | Connector name |
| `connector_type` | string | ✅ | One of the [connector types](#connector-types) |
| `team_id` | UUID | ✅ | Team that owns the connector |
| `json_configuration` | object | ✅ | Type-specific configuration (see [Connector configurations](#connector-configurations)) |

**Response (201 Created):**

```json
{
  "id": "a1b2c3d4-e5f6-4a5b-8c9d-0e1f2a3b4c5d",
  "name": "shop-postgres",
  "connector_type": "POSTGRES_SOURCE",
  "team_id": "881e0fce-5caa-4f5c-82c6-5eb883c47100",
  "json_configuration": {
    "host": "pg.company.com",
    "port": 5432,
    "database": "shop",
    "schema": "public",
    "user": "popsink",
    "password": { "valueFrom": { "secretName": "shop-pg", "key": "password" } },
    "whitelist": "public.orders,public.customers"
  },
  "items_count": 0,
  "status": "paused",
  "topics_config_key": "whitelist",
  "target_destination_kind": null,
  "config_hash": "3f1c..."
}
```

Popsink creates **one data model per entry** of the table list, named `{connector name}_{entry}`. The list is `whitelist` for database sources and `topic` for Kafka (`topics_config_key` tells you which). A CDC source with an empty table list is refused.

```
SOURCE_ID=a1b2c3d4-e5f6-4a5b-8c9d-0e1f2a3b4c5d
```

List the data models it produced:

```bash
curl "$POPSINK_URL/api/datamodels/?source_connector_id=$SOURCE_ID" \
  -H "Authorization: Bearer $TOKEN"
```

```json
{
  "items": [
    {
      "id": "0c7e6a1e-2b1f-4e7a-9a43-5d2f8b1c9e01",
      "name": "shop-postgres_public.orders",
      "source_name": "shop-postgres",
      "source_schema": "public",
      "source_table": "orders",
      "default_target_table": "orders",
      "status": "paused",
      "enabled": true,
      "subscription_count": 0
    },
    { "id": "7d1f...", "name": "shop-postgres_public.customers", "...": "..." }
  ],
  "total": 2, "page": 1, "size": 50, "pages": 1
}
```

To capture more tables later, `PATCH` the connector with a longer `whitelist`: the new entries become new data models.

## Step 7: Subscribe the data models to the target

A subscription delivers one data model to one target connector:

```bash
curl -X POST "$POPSINK_URL/api/subscriptions/" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "orders-to-snowflake",
    "datamodel_id": "0c7e6a1e-2b1f-4e7a-9a43-5d2f8b1c9e01",
    "target_connector_id": "'"$TARGET_ID"'",
    "target_table_name": "ORDERS",
    "backfill": true
  }'
```

**Response (201 Created):**

```json
{ "id": "5efd3d63-a6eb-4b0c-afe9-6ee1d8f5f820" }
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | ✅ | Subscription name |
| `datamodel_id` | UUID | ✅ | Data model to deliver |
| `target_connector_id` | UUID | ✅ | Target connector to write to |
| `target_table_name` | string | ⬜ | Destination table (or topic for a Kafka target). Omit it to use the data model's `default_target_table` |
| `backfill` | boolean | ⬜ | Load the existing rows before streaming changes (default: `false`) |
| `smt_config` | array | ⬜ | Column mapping (see [Mapper configuration](#mapper-configuration)). Omit it to deliver the columns as they are |
| `consumer_id` | string | ⬜ | Consumer group ID (auto-generated if not provided) |
| `error_table_enabled` | boolean | ⬜ | Write rejected records to an error table (default: `false`) |
| `error_table_name` | string | ⬜ | Name of the error table |

To deliver one data model to several targets at once:

```bash
curl -X POST "$POPSINK_URL/api/subscriptions/subscribe-all" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "datamodel_id": "0c7e6a1e-2b1f-4e7a-9a43-5d2f8b1c9e01",
    "target_connector_ids": ["f6e5d4c3-b2a1-4c5d-9e8f-5d4c3b2a1f0e", "9a8b7c6d-5e4f-4a3b-8c2d-1e0f9a8b7c6d"]
  }'
```

```json
{ "ids": ["5efd3d63-...", "b71c09e2-..."] }
```

### Mapper configuration

`smt_config` is a list of output columns. Each entry:

| Field | Type | Description |
|-------|------|-------------|
| `key` | string | Output column name (required) |
| `path` | string | JSON path of the source value (e.g. `$.customer.id`) |
| `static` | string | Static value, instead of `path` |
| `static_on` | string | `always` or `create`: when the static value is written (default: `always`) |
| `cast` | string | `string`, `int`, `float`, `bool`, `date`, `datetime`, `time` |
| `cast_format` | string | Format used by the cast (e.g. a date format) |
| `primary_key` | boolean | Column is part of the primary key (default: `false`) |
| `nullable` | boolean | Column accepts nulls (default: `true`) |
| `concatenate_fields` | array | Build the value by concatenating several fields |
| `hash_method` | string | Hash the value: `md5`, `sha256`, `sha512` |
| `encrypt_method` / `encrypt_key` | string | Encrypt the value with `aes-256-gcm` |

```json
"smt_config": [
  { "key": "order_id", "path": "$.id", "cast": "int", "primary_key": true, "nullable": false },
  { "key": "customer_email", "path": "$.email", "hash_method": "sha256" },
  { "key": "created_at", "path": "$.created_at", "cast": "datetime" },
  { "key": "source", "static": "shop" }
]
```

Test a mapping on a sample message with `POST /smt/process_mapper` (`config`, `table_name`, `message`) before you save it.

## Step 8: Start and monitor

### Start the workers

Connectors are created `paused`. Start the source, then the target:

```bash
curl -X POST "$POPSINK_URL/api/connectors/$SOURCE_ID/start" -H "Authorization: Bearer $TOKEN"
curl -X POST "$POPSINK_URL/api/connectors/$TARGET_ID/start" -H "Authorization: Bearer $TOKEN"
```

Both return `202 Accepted` before the worker converges. Poll the connector until `status` is `live` (or `error`):

```bash
curl "$POPSINK_URL/api/connectors/$SOURCE_ID" -H "Authorization: Bearer $TOKEN" | jq .status
```

| State | Meaning |
|-------|---------|
| `paused` | No worker running |
| `building` | The worker is starting |
| `live` | The worker is running |
| `degraded` | Some of the connector's worker shards are up, others are down |
| `stopping` | A stop was accepted and the worker is draining |
| `error` | The worker failed; check the logs |

Stop a connector with `POST /connectors/{id}/stop`: it reads `stopping`, then `paused` once the worker is gone.

### Enable or disable a single table

You can disable one data model or one subscription without stopping the connector. Popsink restarts the worker automatically to apply the change:

| Action | Endpoint |
|--------|----------|
| Stop capturing a table | `POST /datamodels/{id}/stop` |
| Resume capturing a table | `POST /datamodels/{id}/start` |
| Stop delivering to a target | `POST /subscriptions/{id}/pause` |
| Resume delivering to a target | `POST /subscriptions/{id}/start` |

### Monitor

```bash
# Worker logs (add ?filter_ids=<datamodel or subscription ids> to narrow them)
curl "$POPSINK_URL/api/connectors/$SOURCE_ID/logs" -H "Authorization: Bearer $TOKEN"

# Data models in error in an environment
curl "$POPSINK_URL/api/datamodels/?env=$ENV_ID&state=error" -H "Authorization: Bearer $TOKEN"

# Throughput and freshness of one data model
curl "$POPSINK_URL/api/datamodels/$DATAMODEL_ID/monitoring" -H "Authorization: Bearer $TOKEN"

# Production metrics of a source over the last day
curl "$POPSINK_URL/api/workers/production-metrics?since=2026-10-01T00:00:00Z&connector_id=$SOURCE_ID" \
  -H "Authorization: Bearer $TOKEN"
```

## Step 9: Update a connector or a subscription

### Connector

`PATCH /connectors/{id}` accepts `name`, `json_configuration` and `team_id`. **`json_configuration` is replaced as a whole, not merged**: send the full object, since any key you omit is dropped.

```bash
curl -X PATCH "$POPSINK_URL/api/connectors/$SOURCE_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "json_configuration": {
      "host": "pg.company.com",
      "port": 5432,
      "database": "shop",
      "schema": "public",
      "user": "popsink",
      "password": { "valueFrom": { "secretName": "shop-pg", "key": "password" } },
      "whitelist": "public.orders,public.customers,public.invoices"
    }
  }'
```

A `PATCH` never shrinks the table list: entries you omit from `whitelist` / `topic` are kept. To stop capturing a table for good, delete its data model (`DELETE /datamodels/{id}`). `connector_type` can't change.

### Subscription

All fields of `PATCH /subscriptions/{id}` are optional. The target worker restarts to apply the change. The column mapping is called `mapper_config` here:

```bash
curl -X PATCH "$POPSINK_URL/api/subscriptions/$SUBSCRIPTION_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "target_table_name": "ORDERS_V2",
    "mapper_config": [
      { "key": "order_id", "path": "$.id", "cast": "int", "primary_key": true, "nullable": false }
    ]
  }'
```

## Step 10: Backfill

Reload existing rows into the destinations. Preview first with `POST /backfills/preview`, then trigger:

```bash
curl -X POST "$POPSINK_URL/api/backfills/" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "datamodel_ids": ["0c7e6a1e-2b1f-4e7a-9a43-5d2f8b1c9e01"] }'
```

You can scope a backfill with `source_connector_ids`, `datamodel_ids` and `target_connector_ids`. Follow it with `GET /backfills/status?source_connector_id=<SOURCE_ID>`, and cancel it with `POST /backfills/{run_id}/cancel`.

<Warning>
`"truncate_history": true` empties every destination table before reloading it. It is the only option that deletes data in your warehouse.
</Warning>

## Connector configurations

The `json_configuration` of a connector depends on its type. The examples below cover the most common ones. `GET /connector-types/` returns every type with its form fields, and the `POST /<type>/check-credentials` body in the [OpenAPI schema](#support) documents each field.

### Secrets

Any sensitive field (passwords, private keys, tokens, service-account JSON) accepts either an inline value or a reference to a Kubernetes secret that already exists in the worker namespace:

```json
"password": { "valueFrom": { "secretName": "shop-pg", "key": "password" } }
```

Popsink never stores the referenced value: the worker pod reads it at runtime. We recommend this pattern for API and Terraform consumers. Inline secrets work too, but every read returns them as `"<redacted>"`. `GET /k8s-secrets` lists the secrets available in the worker namespace.

When you re-test an existing connector whose secrets come back as `"<redacted>"`, add `?connector_id=<CONNECTOR_ID>` to its `check-credentials` call: Popsink uses the stored secrets instead of the redacted values.

### SSH tunnel

Database sources (PostgreSQL, MySQL, MariaDB, SQL Server, Oracle, IBM i) can connect through an SSH bastion:

```json
"ssh_tunnel": true,
"ssh_host": "bastion.company.com",
"ssh_port": 22,
"ssh_user": "popsink",
"ssh_private_key": { "valueFrom": { "secretName": "bastion", "key": "id_rsa_b64" } }
```

`ssh_private_key` is the **base64-encoded** private key.

[Kafka source documentation](/connectors/source/kafka)

```json
{
  "bootstrap_servers": "kafka1:9092,kafka2:9092",
```

## Troubleshooting

### `401 Unauthorized`

The token is missing or expired. Log in again, refresh it with `POST /auth/jwt/refresh`, or, with an API key, exchange the key again (its tokens last 10 minutes).

### `400 This endpoint is only available in SELF_HOSTED mode`

API-key login is only available on self-hosted deployments. Use email and password login, or check `GET /config/deployment` to confirm which instance you are calling.

### `403 Forbidden`

You are not a member of the team that owns the resource, or your role doesn't allow writes. Ask a team owner to add you with `POST /teams/{id}/members/bulk`.

### `404` on `/auth/register`

Self-registration is disabled on this deployment. Ask an administrator to invite you.

### `409 Conflict`

A connector with the same name already exists. Pick another name, or send an `Idempotency-Key` header so that retries return the original resource.

### `422 Validation Error`

The body doesn't match the schema. The response names the offending field:

```json
{
  "detail": [
    { "loc": ["body", "json_configuration"], "msg": "Field required", "type": "missing" }
  ]
}
```

### Credentials come back as `"<redacted>"`

That's expected: inline secrets are redacted on every read. Send the full value (or a `valueFrom` reference) again when you `PATCH` the connector, since `json_configuration` is replaced as a whole.

### Connector stuck in `building`

The worker can't start. Read `GET /connectors/{id}/logs`, then check the configuration with the type's `check-credentials` endpoint.

```python
#!/usr/bin/env python3
"""Replicate PostgreSQL tables to Snowflake through the Popsink API."""
import time

import requests

SERVER = "https://<tenant>.<region>.popsink.com/api"
EMAIL = "john.doe@company.com"
PASSWORD = "MySecurePassword123!"
TEAM_ID = "881e0fce-5caa-4f5c-82c6-5eb883c47100"


class PopsinkClient:
    def __init__(self, server: str):
        self.server = server.rstrip("/")
        self.session = requests.Session()

    def login(self, email: str, password: str) -> None:
        response = self.session.post(
            f"{self.server}/auth/jwt/login",
            data={"username": email, "password": password},
        )
        response.raise_for_status()
        token = response.json()["access_token"]
        self.session.headers["Authorization"] = f"Bearer {token}"

    def request(self, method: str, path: str, **kwargs):
        response = self.session.request(method, f"{self.server}{path}", **kwargs)
        response.raise_for_status()
        return response.json() if response.content else None

    def create_connector(self, name: str, connector_type: str, config: dict) -> dict:
        return self.request("POST", "/connectors/", json={
            "name": name,
            "connector_type": connector_type,
            "team_id": TEAM_ID,
            "json_configuration": config,
        })

    def list_datamodels(self, source_id: str) -> list[dict]:
        items, page = [], 1
        while True:
            data = self.request("GET", "/datamodels/", params={
                "source_connector_id": source_id, "page": page, "size": 100,
            })
            items += data["items"]
            if page >= (data["pages"] or 1):
                return items
            page += 1

    def wait_until_live(self, connector_id: str, timeout: int = 600) -> str:
        deadline = time.time() + timeout
        while time.time() < deadline:
            status = self.request("GET", f"/connectors/{connector_id}")["status"]
            if status in ("live", "error"):
                return status
            time.sleep(10)
        raise TimeoutError(f"Connector {connector_id} is still not live")


def main():
    client = PopsinkClient(SERVER)
    client.login(EMAIL, PASSWORD)

    source = client.create_connector("shop-postgres", "POSTGRES_SOURCE", {
        "host": "pg.company.com",
        "port": 5432,
        "database": "shop",
        "user": "popsink",
        "password": {"valueFrom": {"secretName": "shop-pg", "key": "password"}},
        "whitelist": "public.orders,public.customers",
    })
    print(f"Source created: {source['id']}")

    target = client.create_connector("analytics-snowflake", "SNOWFLAKE_TARGET", {
        "account": "myorg-myaccount",
        "user": "POPSINK",
        "role": "POPSINK_ROLE",
        "warehouse": "POPSINK_WH",
        "database": "ANALYTICS",
        "schema": "RAW",
        "private_key": {"valueFrom": {"secretName": "snowflake", "key": "private-key"}},
    })
    print(f"Target created: {target['id']}")

    for datamodel in client.list_datamodels(source["id"]):
        subscription = client.request("POST", "/subscriptions/", json={
            "name": f"{datamodel['source_table'] or datamodel['id']}-to-snowflake",
            "datamodel_id": datamodel["id"],
            "target_connector_id": target["id"],
            "backfill": True,
        })
        print(f"Subscribed {datamodel['name']}: {subscription['id']}")

    for connector in (source, target):
        client.request("POST", f"/connectors/{connector['id']}/start")
        print(f"{connector['name']}: {client.wait_until_live(connector['id'])}")


if __name__ == "__main__":
    main()
```
